# 关键逻辑说明

前半部分保留第一阶段说明，第二阶段新增内容追加在后文对应章节；当前运行环境见[配置说明](../代码/配置说明.md)。

## 1. 代码分工

下表路径均相对于“大作业一/第二阶段/代码”。

| 文件 | 负责内容 |
| --- | --- |
| app/api.py | 接收请求、验证登录、调用业务服务 |
| app/models.py | 检查请求字段、类型、长度，拒绝未知字段 |
| app/domain.py | 题型处理器、配置校验、答案校验及跳转路径计算 |
| app/services.py | 问卷状态、所有权、提交保存及统计 |
| app/database.py | MongoDB 集合结构校验与索引 |
| app/security.py | 密码哈希与登录 token |
| frontend/fill.js | 逐题填写界面、上一题、缓存清理及提交 |

## 2. 账号与权限

| 场景 | 处理方式 |
| --- | --- |
| 注册 | 用户名去除首尾空白，生成不区分大小写的 username_key，唯一索引防止重复注册 |
| 密码保存 | 使用 Argon2 生成密码哈希，不保存明文，不向前端返回哈希 |
| 登录 | 校验用户名和密码，成功后签发带过期时间的 JWT；前端临时保存在 sessionStorage 中 |
| 管理操作 | 后端同时按问卷 ID 和当前用户 ID 查询，其他用户无法读取或管理该问卷 |
| 填写身份 | respondent_id 来自登录认证结果，不能由客户端任意指定 |
| 退出 | 前端删除当前 token；已签发 token 仍按自身过期时间失效，本阶段没有服务端注销名单 |

## 3. 配置与答案校验

配置保存在问卷的 questions 数组中。后端先检查配置是否合理，填写时再按同一题目配置校验答案，不能仅依赖前端提示。

| 题型或场景 | 校验规则 |
| --- | --- |
| 必答 | 只检查实际答题路径中的必答题；被跳过的题目免于必答校验 |
| 单选 | 答案必须是当前题目存在的一个选项 ID |
| 多选 | 选项必须合法且不能重复，检查最少、最多或恰好数量；正数最少或恰好数量同步设为必答 |
| 普通文本 | 去掉首尾空白后按 Unicode 码点计数，检查最小和最大长度 |
| 手机号 | 使用文本题 digits 格式，原始输入只能包含 ASCII 0–9；按字符串保存并保留前导零 |
| 数字 | 接受有效 JSON 数字，拒绝布尔值和数字字符串，检查范围及是否为整数；0 是有效答案 |
| 非必答留空 | 不保存答案对象，不执行格式、长度和范围校验 |
| 配置合法性 | 检查限制上下界、题目与选项 ID、条件类型、跳转目标和规则数量；冲突配置不能保存 |

## 4. 跳转规则与实际路径

每道题的 jump_rules 保存条件运算符、条件值和目标题目 ID。规则按数组顺序判断，不使用固定题号编写某份问卷的分支。

| 来源 | 支持条件 |
| --- | --- |
| 单选 | 选择某个选项 |
| 多选 | 包含任一指定选项、包含全部指定选项、选项集合完全一致 |
| 数字 | 等于、不等于、大于、大于等于、小于、小于等于、闭区间 |

| 顺序 | 路径计算过程 |
| --- | --- |
| 1 | 从问卷第一道题开始，将当前题加入 path |
| 2 | 根据当前题型规范化并校验答案；可选题未答时不触发跳转 |
| 3 | 从上往下判断当前题规则，第一条匹配后进入对应目标 |
| 4 | 没有规则命中则进入下一题；末题完成后进入提交环节 |
| 5 | 提交时由后端重新计算完整路径，只保存路径中的有效答案 |

配置只允许跳到当前题后面的题目，从而避免循环。用户点击“上一题”时返回实际路径的上一道题。更改前题答案后，前端清除后续缓存并重新确认路径；后端也会剔除不在有效路径上的旧答案。

预览和逐题导航使用 partial 模式：计算到首个未确认的题目后返回该题，不强制检查尚未到达的后续必答题。正式提交则检查整条有效路径。预览不写入 responses。

## 5. 问卷状态与截止时间

| 情况 | 处理方式 |
| --- | --- |
| 草稿 draft | 可修改结构，仅创建者预览；没有题目不能发布 |
| 发布 published | 发布前检查题目与规则完整性，且截止时间不能已过期 |
| 关闭 closed | 不再接收新的填写请求，本阶段不提供重新打开 |
| 过期 | 根据 deadline_at 实时判断，不另存过期状态；当前时间达到截止时间即拒绝新提交 |
| 发布后编辑 | 后端禁止修改结构和填写设置，不能只靠前端禁用按钮 |

问卷读取检查与答卷写入是不同操作，不构成跨集合事务。关闭前已经通过服务器检查的并发请求可能继续入库，本阶段按检查时点认定是否接收。

## 6. 提交保存与防重复

| 步骤 | 后端处理 |
| --- | --- |
| 1 | 检查登录身份及 UUID 格式的 submission_key |
| 2 | 若同一问卷、用户、提交键已经保存过，核对规范化答案；相同则返回原答卷，不同则报冲突 |
| 3 | 对新提交检查问卷是否已发布、未关闭且未截止 |
| 4 | 重新计算路径并校验答案，从问卷读取重复填写设置 |
| 5 | 一次写入完整答卷，包括路径、有效答案、填写者 ID 和提交时间 |
| 6 | 捕获唯一索引冲突，区分请求重试与禁止重复填写，返回相应结果 |

| 索引 | 用途 |
| --- | --- |
| survey_id + respondent_id，过滤 repeat_allowed=false | 禁止重复时，一个账号对一份问卷最多保存一份答卷 |
| survey_id + respondent_id + submission_key | 同一次提交的网络重试不重复入库 |

repeat_allowed 由后端从已发布问卷复制，客户端不能自行设置。采用唯一索引保证并发防重，避免“先查有没有，再插入”的竞争问题。允许重复填写时使用新的提交键，保存新的答卷。

## 7. 匿名处理

| 位置 | 处理方式 |
| --- | --- |
| 数据库内部 | 保留 respondent_id，支持登录约束及防重复 |
| 创建者答卷接口 | 使用字段白名单；匿名时不返回填写者 ID、用户名或 submission_key |
| 统计 | 计算次数、内容和平均值，不通过匿名答卷关联显示账号身份 |

匿名指向创建者隐藏账号身份，不代表免登录，也不会自动去除用户在文本答案中主动填写的个人信息。

## 8. 统计计算

统计前先检查创建者权限，再按 survey_id 筛选成功保存的答卷。使用 MongoDB 聚合计算，不预先保存一份容易与答卷不一致的统计计数。

| 统计内容 | 处理方式 |
| --- | --- |
| 总提交份数 | 统计该问卷的答卷文档数，同一账号的多次有效提交独立计数 |
| 单选 | 按题目及选项 ID 分组计数，实际回答该题的答卷计入回答份数 |
| 多选 | 展开选项数组后计数；未被选择的合法选项补成 0 |
| 填空内容 | 按题目查询实际保存的答案，分页展示 |
| 数字平均值 | 对该题有效数字答案求平均；包含数值 0，排除未答和被跳过的题目 |
| 无数字答案 | 平均值返回 null，页面显示“暂无数据” |

## 第二阶段实现逻辑

本节记录已实现的权限、版本、统计与迁移逻辑。“代码与数据”中的数量及授权状态为 2026 年 10 月 22 日验证时点，10 月 23 日另保留了[测试用例第 11 节的界面验收数据](../测试/测试用例.md#11-第二阶段页面操作与原功能回归用例)。版本请求、并发更新与快照绑定的详细约定另见[API 说明](API说明.md#第二阶段接口契约与兼容说明)和[数据库设计](数据库设计.md#第二阶段数据库设计)。

### 权限与统计口径

- 题目使用权与答卷统计权分别授予。拥有原题或收到共享，都不会自动获得其他用户的答卷。
- 问卷创建者在原统计页通过“授权本题统计”向注册用户授权。授权绑定问卷、内部题目和具体版本；已发布过的问卷才可授权，关闭后仍可管理。
- 基础统计与填空内容权限分开。仅获统计授权的用户可进入获授权版本统计，但不能读取源系列历史、其他版本或整份问卷。
- 撤销共享后禁止新增引用、派生及原历史读取；已有问卷仍保留原快照，可原样保存、发布、填写和统计。题库保留失效来源成员，可移除，不能新增选用或升级。
- 归档保留正式版本与原引用，不物理删除。撤销统计授权后，后续请求重新计算可查看范围；不承诺撤销可阻止已经通过授权检查的并发请求。
- 来源按 `(survey_id, question_id, version_id)` 精确确定。数据库聚合同时匹配问卷及其内部题目，避免多个问卷题目 ID 交叉导致串题。
- 统计按有效答卷份数，重复填写分别计数，数字 0 正常计入；未回答与跳过不计入有效回答。选择题按选项次数，数字题提供平均、最小、最大及范围分布。
- 默认数字分布最多十个等宽区间；相同数值使用单区间，浮点精度造成的重复边界会合并。自定义使用 2～20 个严格递增有限数字并附加两端尾区间。
- 基础统计的回答数与可查看内容数分别展示；跨用户内容每条只含 value，不返回填写者、答卷编号、提交编号或逐条时间。文本按纯文本显示。
- 不混合不同版本的统计与平均值。对比只在同系列最多四个版本之间分别展示。

### 代码与数据

原三个集合 users、surveys、responses 保留；新增 question_series、question_versions、question_shares、question_banks、statistic_grants，共八个集合，均初始化结构校验与索引。问卷题目保存内容快照和系列/版本引用，答卷仍使用原问卷内部题目 ID。

题目与绑定在 app/questions.py，原问卷生命周期和提交统计保留在 app/services.py。共享、题库和授权位于 app/collaboration_services.py，跨问卷聚合位于 app/cross_statistics.py，路由位于 app/collaboration_api.py。前端在原模块基础上增加 access.js、banks.js、cross-stats.js，并扩展 questions.js、editor.js 和 stats.js。

版本使用不可变插入、原子编号和唯一请求键支持重试；题库 revision 与问卷 expected_updated_at 检查陈旧保存。系列详情仅在仍可读取源题时展开来源名称与版本，失去权限后保留来源标识，不开放原历史。

第二阶段默认数据库 questionnaire_stage2，应用端口 8001，MongoDB 端口 27018。本机保留的旧数据副本已迁入独立目标库，包含 3 个账号、4 份问卷、8 份答卷、14 个题目系列和 14 个版本。迁移保持原文档 ID、题目、选项、跳转和答案；只读核对原字段、答卷及统计。旧题按原问卷和内部题目各建 v1，不按题干合并。

最终服务检查通过：/api/health 返回第二阶段独立库，/openapi.json 为 2.2.0，新增题库及跨问卷统计接口已加载。再次只读对照保留的来源库，3 个账号、4 份问卷、8 份答卷的原字段与统计一致；共享、题库和统计授权集合当前均为空，浏览器测试数据未写入正式库。
