## 1. 第一阶段已有基础

- 已有账号注册、登录和按创建者检查问卷管理权限的功能。
- 已有问卷创建、草稿编辑、发布、分享、截止和关闭功能。
- 已有单选、多选、文本、数字题，以及校验和条件跳转功能。
- 已有答卷提交、匿名处理、重复填写限制和提交重试处理。
- 已有整份问卷及问卷内单题统计。
- 当前 MongoDB 使用 `users`、`surveys`、`responses` 三个集合，题目嵌入 `surveys.questions`。
- 题目 ID 用于问卷内部的跳转和答案关联，目前没有独立题目库、题目版本及跨问卷题目身份。
- 首次发布后已锁定题目结构，但还没有支持题目复用的版本机制。

## 3. 已确定的业务规则

### 3.1 题目身份与版本

必须区分“同一个题目的版本系列”“某个具体版本”和“该版本在某份问卷中的位置”。不能仅凭题干相同判断为同一道题，也不能直接复用问卷内部题目 ID 作为跨问卷身份。

为题目系列和具体版本分别分配稳定 ID；问卷继续保留原有内部题目 ID，用于题序、跳转和答案关联，同时记录所用版本。一份问卷中同一版本只能添加一次；同一系列的不同版本可以并存，界面标注版本号，统计分别计算。不同问卷可以使用同一版本。

### 3.2 修改与恢复的含义

老师要求已发布问卷不受修改影响，并支持历史恢复，但没有规定所有题目在任何状态下都必须不可修改。

编辑中的题目先保留在当前编辑界面，点击“保存为版本”才产生正式版本，不新增服务端题目草稿自动保存功能。正式版本不可覆盖；后续修改只能保存为新版本，取消编辑不产生新版本。

版本号在同一系列内递增；允许基于任一旧版本创建新版本，并记录直接来源。因此版本关系可以有分支，界面不能只按版本号假定线性继承。保存版本失败重试时不得重复生成版本；并发分配允许有未使用的版本号，但已使用的编号不重复、不回收。

恢复旧版本采用“以旧内容创建新版本”。恢复操作记录当前基准版本和被恢复的历史版本，保留后来版本及其来源。例如恢复 v1 时生成 v4，v2、v3 仍保留。新版本不会自动替换任何问卷或题库中的版本。

### 3.3 问卷选题与更新

选题时绑定具体版本；出现新版本时提示，由问卷创建者主动替换草稿中的版本，已发布问卷保持原版本。题目内容的变动，包括题干、必答、选项和校验配置，均须生成新版本，不能以问卷内修改的方式覆盖所引用的版本。首次发布后的结构锁定继续适用于已关闭的问卷。

保留问卷内的题目内容快照，并记录对应版本；快照由后端从版本生成，客户端不能通过提交版本 ID 加任意内容伪造关联。草稿替换版本时保留问卷内部题目 ID，重新校验整份问卷的选项条件、答案限制和跳转规则；存在失效配置时拒绝保存并指明需修改的规则，不静默删除规则。

### 3.4 题目内容与问卷跳转

原有跳转目标是“当前问卷中的某道题”，同一题复用到其他问卷后，原目标不一定存在。

可复用的题目版本保存题型、题干、必答、选项及校验配置；题目排序、问卷内部题目 ID 和跨题跳转归属于具体问卷。将现有问卷题保存为可复用题时，不将其问卷内 ID 和跳转规则带入题目版本；加入新问卷后跳转规则初始为空，需在新问卷中设置。保留第一阶段只允许向后跳、首条命中生效的规则。

### 3.5 共享范围与权限

老师要求共享给其他用户，未明确要求团队组织、公开题目市场或共享整个题库。

按已注册用户共享题目系列的使用权限，授权期间覆盖该系列现有和后续正式版本，并允许查看其版本历史。题目所有者可以在自己的系列中创建新版本。接收者可以选用共享版本；需要修改时，派生为接收者拥有的新题目系列，记录原系列和原版本来源，后续在自己的系列中维护，不覆盖共享者的原题。派生系列拥有独立身份，不自动与来源题合并统计。

取消共享后，禁止新增问卷引用、新增题库成员、查看源系列历史和再次派生。已采用的问卷和题库条目保留原版本快照及基本标识：已有问卷可继续编辑其他配置、发布、填写和统计，已有题库可展示该条目的快照，但不得再从该条目新增选题或升级版本。撤销前已完成的派生系列继续归接收者所有。后端按操作检查时的授权状态判断，不追溯撤销已接受的并发请求。

使用情况查询：问卷创建者可查看自己问卷的明细；题目所有者可看到跨用户使用数量，以及其他用户已明确向其授权单题统计的问卷基本信息。其他未授权问卷仅显示汇总数量，不泄露标题、创建者身份、答卷或分享链接。共享接收者只能查看自己的使用明细，不获得源题的全局使用清单。

### 3.6 统计范围、版本与隐私

老师要求跨问卷统计，但未明确不同版本能否合并、题目所有者是否有权查看其他用户问卷中的回答。

默认按具体版本汇总，并可查看同一系列各版本的分组结果。本阶段不提供跨版本数值或选项的直接合并，也不按题干相同合并不同系列。页面显示版本、问卷范围和有效回答份数。

题目共享使用权不自动意味着获得他人问卷的统计权。默认汇总自己问卷中的该版本回答；同时提供按“问卷中的题目”授权统计的功能，由问卷创建者明确授权给其他已注册用户，以支持跨用户、跨问卷汇总。授权不开放整份问卷管理或其他题目的答案。

统计授权分为基础统计和填写内容两项：基础统计开放有效回答份数、选项次数和数字统计，不开放逐条文本或数值列表；需要查看填空内容时，问卷创建者另行开启内容权限。任何跨用户授权均不返回填写者账号、用户 ID、答卷 ID、提交编号和逐条提交时间。匿名规则在全部统计入口保持有效。取消统计授权后，后续查询立即按当前权限排除相应问卷题目，不影响问卷原答卷或使用授权。

沿用第一阶段按有效回答计数的方式，数值 0 参与统计，未答及跳过不计入；允许重复填写时，每次有效提交独立计数。单选和多选显示选项计数，文本显示有权限的内容，数字显示份数、平均值、最小值、最大值和范围分布。

数字范围分布默认将当前有权限数据的最小值至最大值等宽分为 10 组，前 9 组左闭右开，最后一组包含最大值；全部值相同时显示一组，无有效回答时显示空分布。支持用户输入严格递增的有限数值边界；首尾增加“小于首边界”和“大于等于末边界”两组，中间使用左闭右开区间，保证每个有效值只计一次。

### 3.7 题库和题目版本的关系

题库归创建者管理，支持修改名称、说明、加入题目、移出题目及删除题库。成员绑定具体版本，同一版本在同一题库只保留一个条目；同系列的不同版本可以并存，同一版本也可以加入多个题库。可加入自己的题目和当前有效共享的题目；有新版本时提示并主动更新，不静默替换。删除题库或移出题目不删除题目历史，也不改变已有问卷。

题库名称、说明、成员管理和选题属于基础管理；公开题库、团队空间、批量导入等不属于当前已明确的必做范围。

### 3.8 旧数据如何接入

现有问卷的题目嵌在问卷中，没有题目库版本 ID。不能直接要求所有旧数据都具有新字段，也不能按题干相同将旧题自动合并。

在独立的第二阶段数据库副本上执行迁移，先验证备份与回退方法。为每个旧问卷内的题目分别建立一个系列和 v1，记录原问卷及原题 ID，不按标题自动合并；迁移后可供创建者复用。迁移保持原问卷、题目、选项、跳转、答卷和答案关联 ID 不变，只补充版本关联等元数据。

迁移可重复执行，以原问卷 ID 和原题 ID 唯一定位迁移产物。旧答卷无需重写答案，可通过问卷内题目映射关联版本；迁移完成的旧数据参与相应版本的跨问卷统计。未迁移数据仍可执行第一阶段操作，但暂不进入题目库的跨问卷统计，界面明确标识；在迁移完成前不混合修改同一问卷。

### 3.9 归档与操作记录

题目系列采用归档，不提供物理删除正式版本的入口；归档后已有问卷和历史保持有效，禁止新增使用，仍可查看自己的历史和统计。题库删除只删除组织容器。版本创建、恢复、派生、共享及统计授权保存真实的创建者、时间和来源信息，便于记录变更和追溯问题。

## 5. 第二阶段测试重点

- 保存题目后多次复用；同一版本被多份问卷使用。
- 共享成功、未授权访问被拒绝、接收者不能覆盖他人的原题。
- 版本来源可追溯，历史恢复不丢失后续历史，多版本能够并存。
- 创建新版本或更新题库后，已发布问卷与原答卷的内容、解释和统计保持一致。
- 在草稿中替换版本后，选项、校验和跳转目标仍然有效。
- 使用情况查询正确，且不泄露无权访问的问卷内容。
- 题库创建、管理、加入题目、选题和更新版本正常。
- 跨问卷统计正确处理权限、版本、重复填写、未回答、跳过和数值 0。
- 旧数据迁移可重复执行，迁移前后原问卷的答卷数量、答案关联及统计结果一致。
- 第一阶段已有账号、发布、填写、跳转、校验、匿名和重复提交测试继续通过。
