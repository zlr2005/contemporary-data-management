# 问序：基于 MongoDB 的问卷系统（第二阶段配置说明）

沿用第一阶段 Python、FastAPI、PyMongo 和原生 HTML/CSS/JavaScript，增加题目保存、复用、版本、共享、题库及跨问卷统计。前后端同源运行，所有业务数据保存到 MongoDB。

本说明保留第一阶段的环境、启动、问卷填写与统计流程，并补充第二阶段已经实现的内容。第二阶段默认应用端口为 `8001`，业务数据库为 `questionnaire_stage2`；本目录不是第一阶段代码的原样副本。

## 代码交付内容核对

| 要求 | 当前文件与实现 |
| --- | --- |
| 后端代码 | `app/`，包括原问卷、答卷与认证服务，以及第二阶段题目版本、共享、题库和跨问卷统计服务；`app/main.py` 已装配原有及新增路由 |
| MongoDB schema | `app/database.py` 中的 `initialize(db)`，包含全部八个集合的 `$jsonSchema` validator 和索引定义；不是另放一份 `.sql` 或 `.json` 文件 |

## 启动

### 本机已有环境

本机已安装依赖。双击 `启动系统.cmd`，或在本“代码”目录终端执行：

```powershell
python start.py
```

随后访问：

- [网页](http://127.0.0.1:8001)
- [可交互 API 文档](http://127.0.0.1:8001/docs)

启动入口会检测项目或上级目录的虚拟环境。没有可用环境时创建本项目 `.venv` 并安装依赖，需要 Python 3.10 以上及可用的 pip。默认需要 `mongod` 在 PATH 中，也支持设置 `MONGOD_PATH`；本机安装位置另有兼容检测。MongoDB 未启动时，以隐藏进程启动项目专用实例，端口 27018，数据目录 `.data/local-mongo`，不会使用之前课程实验的数据目录。停止后端后保留数据库进程和数据，再次启动会复用。

默认仅监听本机，因此分享链接用于本机演示。局域网或公网访问需要另行配置监听地址、域名与部署环境。

配置其他数据库时，将 `.env.example` 复制为 `.env` 后修改。已有 MongoDB 使用 27017 时，可设置 `MONGO_URI=mongodb://127.0.0.1:27017`，不会再自动启动专用实例。系统启动时创建集合、validator 和索引。JWT 密钥未设置时自动保存到 `.local-secret`，它不属于业务数据，不要提交该文件。

第二阶段默认 `MONGO_DATABASE=questionnaire_stage2`、`APP_PORT=8001`；第一阶段默认端口 8000、数据库 questionnaire，不能误将两阶段配置指向同一业务库。启动入口会识别业务库与阶段信息，避免把同端口的其他实例误认为当前服务。

本机旧数据已迁入第二阶段独立库，无需重复复制。其他环境需要迁移时，按下文“第一阶段数据迁移到第二阶段”操作；应用启动只初始化 schema 与索引，不会自动复制或迁移旧库。

### 其他电脑首次配置

安装 Python 3.10 及以上版本（含可用的 pip）和 MongoDB Community Server。在本“代码”目录打开 PowerShell，执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item -LiteralPath .env.example -Destination .env
.\.venv\Scripts\python.exe start.py
```

复制配置文件的命令只用于尚无 `.env` 的新环境；已有配置直接编辑原文件。若 `mongod` 未加入 PATH，在启动前按实际安装位置设置：

```powershell
$env:MONGOD_PATH = 'D:\MongoDB\Server\8.3\bin\mongod.exe'
```

仓库不包含本机数据库、账号和答卷，其他电脑首次运行需自行注册并创建问卷。正常新建数据不需要执行旧库迁移。

### 配置参数

应用从本目录 `.env` 读取配置；同名进程环境变量优先。第二阶段没有新增独立的共享服务或统计服务，仍由同一个 FastAPI 应用提供接口。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `MONGO_URI` | `mongodb://127.0.0.1:27018` | MongoDB 连接；只有默认本机地址在不可用时会由启动入口尝试启动数据库 |
| `MONGO_DATABASE` | `questionnaire_stage2` | 第二阶段独立业务库，避免与第一阶段 `questionnaire` 混用 |
| `APP_PORT` | `8001` | `start.py` 使用的应用端口；第一阶段默认 `8000` |
| `JWT_SECRET` | 留空 | 留空时使用本目录 `.local-secret` 中的持久开发密钥；多实例部署应显式配置相同的随机长字符串 |
| `MONGOD_PATH` | 从进程环境读取 | `mongod.exe` 的实际路径，在 PowerShell 中设置后再启动；启动器也会搜索 PATH |
| `TEST_MONGO_URI` | `mongodb://127.0.0.1:27018` | pytest 专用连接，不改变正式应用的数据库配置 |

停止后端时在其终端按 `Ctrl+C`。启动器保留 MongoDB 进程和数据；若 27018 已有可用 MongoDB，直接复用该服务，再以库名区分业务数据。

### 检查启动结果

启动后在另一个 PowerShell 终端执行：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8001/api/health'
```

默认配置应返回 `status=ok`、`database=MongoDB`、`database_name=questionnaire_stage2` 和 `stage=2`。访问 `/docs` 应同时看到原问卷接口与题目系列、版本、共享、题库、单题统计授权及跨问卷统计接口；当前 API 版本为 `2.2.0`。修改端口或库名后，应按实际配置核对。

## MongoDB schema 与初始化

实际 schema 以 [`app/database.py`](app/database.py) 为准，`connect(settings)` 会调用 `initialize(db)`。应用启动时自动创建缺失的集合，并通过 `collMod` 更新已有集合的 validator，再创建索引。全部集合使用 `validationLevel=strict` 和 `validationAction=error`。

| 集合 | 阶段 | 主要字段与作用 |
| --- | --- | --- |
| `users` | 第一阶段保留 | 用户名、规范化用户名、密码哈希、创建时间 |
| `surveys` | 第一阶段扩展 | 拥有者、状态、分享码、填写设置、题目与跳转快照；第二阶段每题增加 `series_id`、`version_id` |
| `responses` | 第一阶段保留 | 问卷、填写者、提交请求键、实际路径、答案及提交时间；答案继续通过原 `question_id` 关联 |
| `question_series` | 第二阶段新增 | 拥有者、名称、归档状态、版本计数、派生来源及旧题迁移键 |
| `question_versions` | 第二阶段新增 | 系列、版本号、题目内容、父版本、恢复来源、操作类型和幂等请求键 |
| `question_shares` | 第二阶段新增 | 系列、接收者、授权人、有效或撤销状态及授权时间 |
| `question_banks` | 第二阶段新增 | 拥有者、名称、说明、题目成员版本及内容快照、修订号；每库最多 500 个成员 |
| `statistic_grants` | 第二阶段新增 | 问卷、内部题目 ID、具体版本、接收者、授权状态，以及是否允许查看填空内容 |

关联 ID 使用 MongoDB `ObjectId`，时间使用 BSON `date`；问卷内部题目、选项与跳转 ID 保留原字符串格式。版本内容保存题型、标题、必答、选项和校验配置，问卷自己的跳转规则保留在问卷快照中。

`surveys.schema_version` 兼容 `1` 和 `2`；版本 2 要求每题具有系列与版本引用。其余七个集合当前的 `schema_version` 仍为 `1`，这是各集合的结构版本，不代表它们属于第一阶段。新建及完成迁移的第二阶段问卷使用结构版本 2；旧答卷不重写。

关键索引包括用户名与分享码唯一索引、禁止重复填写的部分唯一索引、提交重试唯一索引、`(series_id, version_no)` 版本唯一索引、`(created_by, request_key)` 版本请求唯一索引，以及共享和统计授权的组合唯一索引。问卷还为 `questions.series_id`、`questions.version_id` 建立查询索引。

如需手动初始化，在已经安装依赖、MongoDB 已启动且配置正确的本目录执行：

```powershell
python scripts/init_db.py
```

该脚本与应用调用相同的初始化函数，会处理全部八个集合；目前终端只打印原三个集合的索引摘要，不能据此判断新增集合缺失。此操作创建或更新 schema 与索引，不负责给旧问卷补题目版本。

## 第一阶段数据迁移到第二阶段

本机此前已完成迁移并保存核对记录，不要重复复制。以下命令只用于其他环境确有旧库需要迁移的场景，均在本“代码”目录使用已安装依赖的 Python 执行。示例来源库 `questionnaire` 应替换为实际已备份核对的旧库或副本名。

```powershell
# 仅预览来源数量和目标库中待迁移的问卷，不修改 schema 或数据
python scripts/migrate_stage2.py --copy-from questionnaire

# 确认目标库为空、来源已备份，并停止目标库用户写入后，复制并迁移
python scripts/migrate_stage2.py --copy-from questionnaire --apply

# 已复制或中断后继续迁移，仅补齐目标库未完成的旧问卷
python scripts/migrate_stage2.py --apply
```

目标库默认取 `MONGO_DATABASE`，也可用 `--database` 指定；迁移脚本只允许以 `_stage2` 结尾的业务库或 `questionnaire_test_` 开头的测试库。复制前检查目标的用户、问卷、答卷、题目系列与版本集合均为空；不会覆盖已存在的业务文档。来源只读，保留原 `_id`、题目与选项 ID、跳转、时间及答案；按“原问卷 ID + 内部题目 ID”为旧题建立 v1，不按相同题干合并。复制并迁移后逐文档核对原字段、答卷和原统计；再次执行时去掉 `--copy-from`。

## 使用流程

### 保留的第一阶段流程

1. 注册并登录，密码至少 8 个字符。
2. 创建问卷，填写标题、说明、北京时间截止时间和填写设置。
3. 添加题目，设置选项、必答与校验条件。
4. 在来源题目下添加跳转规则，选择条件与后面的目标题目。规则从上往下匹配；多选条件按 Ctrl 选择多个选项。
5. 保存后预览。预览验证实际流程，不保存正式答卷。
6. 保存并发布，返回列表复制分享链接。
7. 填写者登录后填写并提交。在统计页面查看整份问卷、单题统计及填空内容。

### 第二阶段使用流程

1. 在“题目管理”创建题目，保存为 v1；也可在原问卷编辑器直接编题，由后端建立相应的版本关联。
2. 在草稿中“从已有题目选取”，明确选择版本，设置问卷内跳转后保存整份问卷。同一版本不能在同卷重复加入。
3. 在题目详情基于所选版本修改形成新版本；恢复旧内容也会产生新版本。返回草稿主动替换版本，再保存整份问卷，已发布问卷继续保留原版本。
4. 在“共享使用”按注册用户名授权。接收者从“共享给我的”复用；需要修改共享题时，先派生为自己的系列。
5. 创建题库，添加题目和具体版本。题库成员有新版本时主动更新；从题库选择题目后，仍须保存目标问卷，题库更新不会自动修改已有问卷。
6. 问卷发布并产生答卷后，问卷拥有者在原统计页“授权本题统计”；按需单独开放填空内容。题目共享本身不会授予他人答卷访问权。
7. 在“跨问卷统计”选择具体版本，查看自己的问卷或他人明确授权的单题，核对汇总、来源和数字分布；多个版本分别对比，不混算平均值。
8. 撤销共享或归档题目后，原问卷快照和答卷继续可用；后续新增引用受限。撤销统计授权后，后续统计请求重新计算授权范围。

开发机保留 2026 年 10 月 23 日的验收账号、三份验收问卷和四份答卷供复查；账号与数据库均不随提交副本分发。验收结束时共享、统计授权已撤销，题库已删除，所以当前统计范围与授权有效时的截图可能不同。具体预期值见[测试用例第 11 节的操作验收结果](../测试/测试用例.md#11-第二阶段页面操作与原功能回归用例)。其他电脑请自行注册使用。

## 测试

开发时曾复用“大作业一/.venv”。提交副本请按前文在当前“代码”目录创建独立 `.venv`；MongoDB 默认地址为 `127.0.0.1:27018`。在本代码目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q --tb=short
```

## 当前边界

不保存未提交填写草稿；返回修改前题且更改答案时，清除其后缓存并重新填写后续路径。问卷发布后只允许修改标题、说明、截止时间和关闭。关闭与提交按服务器读取检查时刻判定，已通过检查的并发请求可能继续入库，与数据库设计约定一致。

统计按答卷份数计数。匿名针对创建者的账号身份展示，内部仍保存填写者 ID；题目中主动填写的个人信息不会自动消除。手机号按纯数字文本处理，不参与数字平均值。

跨问卷统计只读取自己的问卷或有效单题授权，基础统计权不自动开放填空内容。跨用户内容不返回填写者身份、答卷编号和逐条提交时间。数字 0 正常计入，跳过或未回答不计入有效回答；不同版本不合并统计。权限撤销在后续请求检查时生效，不能追回已返回的数据或保证阻止已通过检查的并发请求。

## 常见运行问题与提交范围

| 现象 | 检查方法 |
| --- | --- |
| 找不到 `mongod` | 安装 MongoDB Server，核对 PATH，或在启动前设置正确的 `MONGOD_PATH` |
| 数据库连接失败 | 核对 `MONGO_URI`、服务端口与 `.data/local-mongo.log`；自定义连接不会由启动器自动拉起 MongoDB |
| 8001 端口被占用 | 检查该地址 `/api/health` 的库名和 `stage`；若为其他服务，修改 `.env` 的 `APP_PORT` 后重启 |
| 页面仍显示旧界面 | 使用 `http://127.0.0.1:8001/?v=20261023` 并强制刷新，核对后端为第二阶段服务 |
| 看不到题目或他人答卷 | 核对账号、题目共享与单题统计授权；题目使用权和统计权分别授予，填空内容还需单独开放 |
| 旧问卷不能使用新增复用与跨问卷统计 | 先对独立第二阶段库执行迁移，不能只初始化 schema；旧问卷未迁移时仍可使用原阶段功能 |
| pytest 连接失败 | 确保 MongoDB 已启动；自定义端口时显式设置 `TEST_MONGO_URI`，仅启动 pytest 不会自动启动数据库 |

提交时保留源码、前端、依赖清单、`.env.example`、`.gitignore`、启动入口、配置说明及配套文档和测试材料。不要提交 `.venv/`、`.data/`、`.env`、`.local-secret`、`__pycache__/`、`.pytest_cache/` 和 `*.pyc`。运行数据、账号及本机密钥不属于代码交付内容。
