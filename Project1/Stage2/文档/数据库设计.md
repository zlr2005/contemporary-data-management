# 数据库设计

前半部分保留第一阶段说明，第二阶段新增内容追加在后文对应章节；当前运行环境见[配置说明](../代码/配置说明.md)。

数据库使用 MongoDB，分为 users、surveys、responses 三个集合。

## 1. 集合划分

| 集合 | 保存内容 | 关联方式 |
| --- | --- | --- |
| `users` | 用户名、密码哈希、注册时间 | `_id` 标识用户 |
| `surveys` | 创建者、问卷设置、题目、校验与跳转规则 | `owner_id` 引用 `users._id` |
| `responses` | 每次提交的填写者、问卷、答题路径及答案 | `survey_id` 引用 `surveys._id`；`respondent_id` 引用 `users._id` |

## 2. 用户集合 users

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | ObjectId | 是 | 用户唯一标识 |
| `username` | string | 是 | 去除首尾空白后的用户名，不允许为空 |
| `username_key` | string | 是 | 用户名去除首尾空白后进行 Unicode casefold 的结果，用于登录查询和唯一约束 |
| `password_hash` | string | 是 | 密码哈希，使用成熟密码哈希库生成，不保存明文密码 |
| `created_at` | date | 是 | 服务端生成的注册时间 |
| `schema_version` | int | 是 | 固定为 `1` |

## 3. 问卷集合 surveys

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | ObjectId | 是 | 问卷 ID |
| `owner_id` | ObjectId | 是 | 创建者用户 ID，来自登录身份 |
| `title` | string | 是 | 非空问卷标题 |
| `description` | string | 是 | 问卷说明，默认空字符串 |
| `share_code` | string | 是 | 随机生成且唯一的链接标识，路径为 `/survey/{share_code}` |
| `status` | string | 是 | `draft`、`published`、`closed` 三选一 |
| `allow_anonymous` | bool | 是 | 是否匿名，默认 `false`；为 `true` 时所有该问卷答卷对创建者匿名 |
| `allow_repeat` | bool | 是 | 是否允许同一账号重复填写，默认 `false` |
| `deadline_at` | date 或 null | 是，可为 null | 截止时刻；null 表示不设置截止时间 |
| `questions` | `array<object>` | 是 | 按展示顺序排列的题目，草稿可为空，发布时至少一道题 |
| `published_at` | date 或 null | 是，可为 null | 首次发布时间；草稿为 null |
| `closed_at` | date 或 null | 是，可为 null | 手动关闭时间；未关闭时为 null |
| `created_at` | date | 是 | 创建时间 |
| `updated_at` | date | 是 | 最近修改时间 |
| `schema_version` | int | 是 | 固定为 `1` |

## 4. 题目结构 questions

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 问卷内部唯一、创建后稳定不变的题目 ID |
| `type` | string | 是 | `single`、`multiple`、`text`、`number` |
| `title` | string | 是 | 非空题目标题 |
| `required` | bool | 是 | 是否必答，默认 `false` |
| `options` | `array<object>` | 是 | 单选、多选的选项；填空题使用空数组 |
| `validation` | object | 是 | 与题型对应的校验配置 |
| `jump_rules` | `array<object>` | 是 | 有序跳转规则列表，默认空数组 |

## 5. 校验规则 validation

| 题型 | 字段及类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 单选 | 无专属字段，使用 `{}` | — | 结合 `required` 检查，答案必须属于当前题目选项 |
| 多选 | `min_choices`: int 或 null | 否 | 最少选择数量，缺省表示无限制 |
| 多选 | `max_choices`: int 或 null | 否 | 最多选择数量，缺省表示无限制 |
| 多选 | `exact_choices`: int 或 null | 否 | 恰好选择数量，设置时不得同时设置有效的 min/max |
| 文本 | `min_length`: int 或 null | 否 | 最小文本长度，缺省表示无限制 |
| 文本 | `max_length`: int 或 null | 否 | 最大文本长度，缺省表示无限制 |
| 文本 | `format`: string | 是 | `plain` 或 `digits`；手机号使用 `digits` |
| 数字 | `min_value`: number 或 null | 否 | 最小值，包含边界 |
| 数字 | `max_value`: number 或 null | 否 | 最大值，包含边界 |
| 数字 | `integer_only`: bool | 是 | 是否必须为整数 |

## 6. 跳转规则 jump_rules

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 当前题目内唯一的规则 ID |
| `operator` | string | 是 | 条件运算符，见下表 |
| `value` | string、`array<string>`、number 或 object | 是 | 比较条件值，类型取决于运算符 |
| `target_question_id` | string | 是 | 同份问卷中的目标题目 ID |

### 跳转条件

| 来源题型 | operator | value 示例及语义 |
| --- | --- | --- |
| 单选 | `eq` | `"o1"`：选择该选项 |
| 多选 | `contains_any` | `["o1", "o2"]`：至少包含其中一个 |
| 多选 | `contains_all` | `["o1", "o2"]`：全部包含，允许额外选项 |
| 多选 | `exact_set` | `["o1", "o2"]`：选项集合完全一致，与顺序无关 |
| 数字 | `eq`、`ne`、`gt`、`gte`、`lt`、`lte` | 数值：等于、不等于、大于、大于等于、小于、小于等于 |
| 数字 | `between` | `{"min": 18, "max": 60}`：包含两端的区间；min、max 均为必填 number |

## 7. 答卷集合 responses

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | ObjectId | 是 | 本次答卷 ID |
| `survey_id` | ObjectId | 是 | 所属问卷 ID |
| `respondent_id` | ObjectId | 是 | 登录填写者 ID，即使匿名也在内部保存 |
| `repeat_allowed` | bool | 是 | 服务端从已发布问卷复制的重复填写设置，用于部分唯一索引 |
| `submission_key` | string | 是 | 每次填写生成的 UUID，请求重试沿用；成功后再次填写生成新值 |
| `path` | `array<string>` | 是 | 后端重新计算的实际经过题目 ID，包含经过但未答的可选题 |
| `answers` | `array<object>` | 是 | 有效路径内实际填写的答案，题目 ID 不重复 |
| `submitted_at` | date | 是 | 服务器检查并接收本次提交的 UTC 时间 |
| `schema_version` | int | 是 | 固定为 `1` |

### 答案结构 answers

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `question_id` | string | 是 | 题目 ID，必须在 path 内 |
| `value` | string、`array<string>` 或 number | 是 | 单选为选项 ID；多选为无重复选项 ID 数组；文本和手机号为字符串；数字为数值 |

## 8. 索引设计

| 集合 | 索引字段 | 类型 | 作用 |
| --- | --- | --- | --- |
| users | `username_key: 1` | 唯一 | 防止重复用户名并支持登录查询 |
| surveys | `share_code: 1` | 唯一 | 按分享链接定位问卷，发生随机码冲突时重新生成 |
| surveys | `owner_id: 1, created_at: -1` | 普通复合 | 按创建者列出问卷，并按创建时间倒序 |
| responses | `survey_id: 1, submitted_at: -1` | 普通复合 | 查询某份问卷答卷并支持统计入口筛选 |
| responses | `survey_id: 1, respondent_id: 1` | 部分唯一 | 仅对 `repeat_allowed: false` 的答卷限制一个账号一份 |
| responses | `survey_id: 1, respondent_id: 1, submission_key: 1` | 唯一 | 同一次提交的网络重试不重复生成答卷 |

## 9. 统计方式

| 指标 | 计算方式 |
| --- | --- |
| 问卷提交份数 | 该问卷 responses 文档数 |
| 单选各选项次数 | 按 question_id 筛选答案，再按 value 分组计数 |
| 单选总回答份数 | 实际存在该题答案的答卷数 |
| 多选各选项次数 | 展开该题 value 数组后，按选项 ID 分组计数 |
| 文本填写内容 | 返回该题实际保存的字符串，可分页展示 |
| 数字填写内容与平均值 | 返回该题数值，并对有效数值计算平均值；0 计入，无答案显示“暂无数据” |

## 10. 主要设计约定

| 内容 | 处理方式 |
| --- | --- |
| 集合关联 | owner_id、respondent_id 关联 users._id，survey_id 关联 surveys._id；后端检查引用是否有效 |
| 题目与选项 | 题目放在问卷内部，选项放在题目内部；选项包含 id 和 label，均为必填字符串；顺序按数组排列，关联使用稳定 ID |
| 数据拆分 | 题目配置经常一起读取，所以嵌入问卷；答卷会持续增加，所以单独保存，避免问卷文档过大 |
| MongoDB 适用性 | 嵌套文档适合保存不同题型、校验和跳转配置，不必将每种配置拆成单独集合 |
| 用户名与密码 | 用户名去除首尾空白后生成不区分大小写的 username_key；密码只保存哈希 |
| 匿名填写 | 填写者仍需登录，内部保存用户 ID；匿名问卷不向创建者返回填写者 ID、用户名及 submission_key |
| 重复填写 | 创建者设置，默认不允许；repeat_allowed 由后端从问卷复制，禁止客户端自行设置；并发限制依靠部分唯一索引 |
| 提交重试 | 同一次提交沿用 submission_key；相同键和相同内容返回原答卷，相同键但内容不同则提示冲突 |
| 题目校验 | 所有题型支持必答，默认非必答；正数的多选最少或恰好数量要求同步设为必答；校验上下界不得矛盾 |
| 手机号 | 使用文本题加 digits 格式，仅允许 ASCII 0–9，拒绝空格等其他字符；按字符串保存，保留前导零，不计算平均值 |
| 文本长度 | 普通文本去除首尾空白后按 Unicode 码点计数；手机号直接校验原始输入，不先去除空格 |
| 跳转 | 只允许向后跳，首条命中规则生效；未命中进入下一题，最后一题完成后提交；未填写题目不触发规则 |
| 答题路径 | 后端重新计算路径，仅校验路径内必答题；改答案后清除失效路径上的旧答案；path 保留经过但未答的可选题，answers 不保存空答案 |
| 问卷状态 | draft 为草稿，published 为已发布，closed 为已关闭；只有已发布且未截止的问卷可以提交 |
| 截止时间 | 保存为 UTC，展示为北京时间；以服务器接收检查时刻为准，到达截止时刻拒绝新提交；关闭检查前已接收的并发请求可能继续入库 |
| 发布后修改 | 首次发布后锁定题目、选项、校验、跳转、匿名和重复填写设置；仅允许修改标题、说明、截止时间及关闭问卷 |
| 统计口径 | 每份成功提交的答卷独立计数，不按账号去重；跳过和未回答的题目不计入有效回答，数值 0 正常参与平均值 |
| 权限与完整性 | 查询管理数据及统计前检查创建者；数据库校验必填字段与类型，后端检查状态、路径及跨集合关联 |
| 数据保留 | 第一阶段保留已发布问卷和正式答卷；schema_version 表示数据结构版本，便于第二阶段扩展 |

## 第二阶段数据库设计

本设计依据已确定的《第二阶段需求梳理.md》，在第一阶段 Python、FastAPI、PyMongo 和 MongoDB 系统上增加题目复用、版本、共享、题库及跨问卷统计。保留问卷内题目快照和原有答卷结构，避免重写第一阶段核心业务。

设计形成于 2026 年 10 月 22 日。八个集合的结构校验、索引及业务服务均已实现，旧数据迁移已完成核对；实际结果见[第二阶段实现与验证](../测试/测试用例.md#第二阶段实现与验证)。前文保留第一阶段数据库设计，本节追加第二阶段设计依据，具体模块划分和已验证范围以当前实现记录为准。

### 1. 原设计的问题与扩展方式

第一阶段题目只存于 `surveys.questions`，其 `id` 服务于问卷内部，无法单独表达复用关系、共享权限或版本历史。答卷通过 `survey_id` 和 `answers.question_id` 找题，原统计也按这两个字段查询。

第二阶段将可复用题目保存为独立的系列和不可变版本，同时在问卷中继续嵌入内容快照及版本引用。题目内容与引用版本保持一致，题序和跳转仍在问卷中配置。原有答案无需改写，跨问卷统计通过问卷题目到版本的映射定位。

不额外维护“题目使用次数”或独立使用关系集合：从问卷的引用字段查询，避免更新问卷和更新使用关系时出现双份记录不一致。

### 2. 集合总览

| 集合 | 变化 | 保存内容 |
| --- | --- | --- |
| `users` | 保留 | 第一阶段账号，结构版本继续为 1 |
| `surveys` | 扩展 | 原问卷、题目快照及新增版本引用；支持结构版本 1、2 |
| `responses` | 保留 | 原答卷、路径和答案；无需增加版本字段，结构版本继续为 1 |
| `question_series` | 新增 | 题目系列、归属、归档状态、版本号分配计数及来源 |
| `question_versions` | 新增 | 不可变的题目内容、版本号、直接来源和恢复来源 |
| `question_shares` | 新增 | 系列向指定用户授予使用权的当前状态 |
| `question_banks` | 新增 | 用户的题库和所选具体版本 |
| `statistic_grants` | 新增 | 问卷创建者对指定问卷题目授予的统计权限 |

新增集合各自使用 `schema_version: 1`；该字段表示文档结构，不表示题目业务版本。业务版本号使用 `version_no`。

### 3. 题目系列 question_series

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `_id` | ObjectId | 系列身份，即 `series_id` |
| `owner_id` | ObjectId | 拥有者，关联 `users._id` |
| `name` | string | 系列管理名称，可改名，不影响已保存题干 |
| `status` | string | `active` 或 `archived` |
| `version_counter` | int | 分配版本号的计数器，允许因失败留空号 |
| `forked_from_series_id` | ObjectId 或 null | 派生时记录的源系列 |
| `forked_from_version_id` | ObjectId 或 null | 派生时记录的源版本 |
| `legacy_key` | string，可缺省 | 旧题迁移键，由原问卷 ID 和原题目 ID 组合 |
| `created_at`、`updated_at` | date | UTC 时间 |
| `schema_version` | int | 新集合结构版本，初始 1 |

拥有者才能修改系列名称、归档、共享及在本系列中创建版本。共享接收者修改题目时创建自己的系列，通过派生字段保留来源。系列中尚无成功保存的版本时不显示为可选题。

系列归档阻止新增引用、派生和版本更新，保留现有引用、历史、使用情况和统计；需要继续维护时由拥有者恢复为 active。

### 4. 题目版本 question_versions

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `_id` | ObjectId | 具体版本身份，即 `version_id` |
| `series_id` | ObjectId | 所属系列 |
| `version_no` | int | 系列内唯一、单调分配的正整数 |
| `parent_version_id` | ObjectId 或 null | 编辑所基于的版本；本系列首次版本为 null |
| `restored_from_version_id` | ObjectId 或 null | 恢复操作所取内容的旧版本；普通修改为 null |
| `operation` | string | `create`、`edit`、`restore`、`fork`、`migrate` |
| `content` | object | `type`、`title`、`required`、`options`、`validation` |
| `created_by` | ObjectId | 创建者 |
| `created_at` | date | UTC 时间 |
| `request_key` | string | 客户端本次保存操作的 UUID，用于重试去重 |
| `request_hash` | string | 规范化保存请求的摘要，检查相同键是否用于不同请求 |
| `schema_version` | int | 初始 1 |

`content.options` 继续使用原选项 `id` 和 `label`，`validation` 沿用第一阶段配置。题型仍为 single、multiple、text、number。选项身份在一个版本内有效，不根据跨版本 ID 相同就合并统计。

版本文档只插入和读取，不提供修改或物理删除接口。创建新版本时确认系列所有权、状态、来源归属和内容有效性；恢复版本时复制历史 content，同时记录操作基准 parent 和 restored_from。派生系列的 v1 通过系列来源字段指向外部原版本，其 parent 为 null。

保存时先检查 `(created_by, request_key)`，相同键和相同规范化请求返回已有版本，相同键但内容不同返回冲突。通过系列文档原子递增计数器分配编号后插入版本；唯一索引处理并发重复，失败留号不回收。计数器不等于“最新成功版本”，最新版本按实际存在的最大 version_no 查询。迁移创建 v1 时先确保计数器至少为 1。

题目编辑草稿仅存在当前编辑界面，不新增数据库草稿集合。单个版本和请求沿用合理大小限制，后端同时检查内容格式和 BSON 大小。

### 5. 扩展 surveys.questions

保留以下字段：`id`、`type`、`title`、`required`、`options`、`validation`、`jump_rules`。

结构版本 2 的每个题目新增：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `series_id` | ObjectId | 关联 `question_series._id` |
| `version_id` | ObjectId | 关联 `question_versions._id` |

问卷题目原字段中除 id、jump_rules 外的内容来自版本 content；不在问卷中冗余保存 version_no，管理端展示时批量读取版本信息。`id` 继续是当前问卷内部的字符串题目 ID，数组顺序继续代表题序。

新选题流程：检查系列 active 和当前使用权限，按 version_id 读取版本，由后端构造快照和新的问卷内 id，jump_rules 初始为空。新建题也可在原问卷编辑页操作，首次保存时先创建系列及 v1，再加入问卷，保留第一阶段直接编题建卷的使用方式。

修改草稿中的自有题时，保存内容变化为新版本并显式绑定；修改共享题时先派生。未变化的题不生成版本。替换版本保留问卷内 id；检查同一问卷的 version_id 不重复，随后重新验证整份问卷的规则，失败时返回错误，原问卷不变。已先保存成功的新版本可以保留在题目管理页，不因问卷保存失败而删除。

已有引用在撤销共享或归档后仍可保留；后端通过原问卷的 id、version_id 和快照验证其是原有引用。新增引用、换版本、克隆引用、从题库再次选题都重新检查权限，不能通过伪造旧引用绕过。正常保存和发布不要求仍持有源题使用授权，但不能变更原快照。

首次发布后继续锁定全部题目结构，包括 version_id、series_id、题序及跳转；关闭问卷不解除锁定。只允许第一阶段已支持的元数据修改和状态操作。迁移可补充来源字段，但不得更改题目内容。

服务端客户端边界：HTTP JSON 中 ID 使用字符串，由后端验证并转换成 ObjectId。填写端继续只接收第一阶段答题所需字段，不暴露系列所有者、共享名单等管理数据。

### 6. 题目共享 question_shares

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `_id` | ObjectId | 授权记录 ID |
| `series_id` | ObjectId | 被共享系列 |
| `grantee_id` | ObjectId | 接收者用户 |
| `granted_by` | ObjectId | 当前系列拥有者 |
| `status` | string | `active` 或 `revoked` |
| `created_at`、`updated_at` | date | 首次创建和最近状态修改时间 |
| `revoked_at` | date 或 null | 撤销时间 |
| `schema_version` | int | 初始 1 |

同一系列和接收者只有一条当前授权记录，重复授权或撤销均可幂等执行。重新授权更新同一记录。使用权限覆盖系列全部正式版本，不自动授予统计、转授权或原系列编辑权。

当前记录用于权限判断，保留首次和最近变更时间；不宣称它是完整的多次撤销历史。如后续需要完整授权审计，再增加独立事件记录。来源引用不赋予额外读取权限，撤销后展示派生来源时只保留来源标识，不开放源版本详情。

### 7. 题库 question_banks

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `_id` | ObjectId | 题库身份 |
| `owner_id` | ObjectId | 管理者 |
| `name`、`description` | string | 名称和说明 |
| `items` | array<object> | 按展示顺序保存成员 |
| `items[].series_id`、`items[].version_id` | ObjectId | 绑定的系列与具体版本 |
| `items[].content` | object | 后端生成的版本快照，撤销共享后用于展示既有条目 |
| `items[].added_at` | date | 加入时间 |
| `revision` | int | 乐观并发控制序号 |
| `created_at`、`updated_at` | date | UTC 时间 |
| `schema_version` | int | 初始 1 |

采用嵌入成员，因题库与选题列表经常一起读取；成员最多 500 个，并检查文档小于 15 MiB，避免无限增长。规模超过该限制时再拆分成员集合，不提前引入额外关系集合。

新增和替换成员需要有效使用权限，校验版本与系列一致、快照一致及 version_id 不重复；通过 `_id + owner_id + revision` 条件更新防止覆盖并发修改。MongoDB 文档校验不代替应用层的成员唯一性检查。删除题库只删除本题库文档，不级联删除版本、授权或问卷。

### 8. 跨问卷统计授权 statistic_grants

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `_id` | ObjectId | 授权 ID |
| `survey_id` | ObjectId | 被授权问卷 |
| `question_id` | string | 该问卷内的题目 ID |
| `version_id` | ObjectId | 授权时绑定的具体版本 |
| `grantee_id`、`granted_by` | ObjectId | 接收者和问卷创建者 |
| `allow_contents` | bool | 是否允许查看逐条填空内容，默认 false |
| `status` | string | active 或 revoked |
| `created_at`、`updated_at`、`revoked_at` | date 或 null | 对应创建、更新和撤销时间 |
| `schema_version` | int | 初始 1 |

仅问卷创建者可授权；针对已首次发布的问卷题目授权，关闭后仍可授权历史统计。授权以 survey_id、question_id、version_id 联合限定，避免错误归入同一问卷的其他题。共享题目不是统计授权的前提，统计授权本身也不授予复用题目或查看源系列历史的权利。

单题统计授权允许读取对应版本的必要题目快照、该问卷标题和状态，不开放其他题目。统计授权不扩展原有整卷统计、答卷列表和问卷管理接口；新增跨问卷单题统计接口单独组合数据及检查权限。

### 9. 索引与校验

保留第一阶段全部唯一索引和查询索引，新增如下索引。以实现后的 explain 和实际数据量评估是否调整，本文不宣称已完成性能验证。

| 集合 | 索引字段 | 目的 |
| --- | --- | --- |
| question_series | owner_id, created_at 降序 | 自有题目列表 |
| question_series | legacy_key，部分唯一 | 仅对具有字符串迁移键的记录生效，防止重复迁移 |
| question_versions | series_id, version_no，唯一 | 系列内版本唯一和历史查询 |
| question_versions | created_by, request_key，唯一 | 保存版本请求重试去重 |
| question_shares | series_id, grantee_id，唯一 | 防止重复授权记录 |
| question_shares | grantee_id, status | 我可用的共享题目 |
| question_banks | owner_id, updated_at 降序 | 自有题库列表 |
| statistic_grants | survey_id, question_id, grantee_id，唯一 | 单题统计授权唯一 |
| statistic_grants | grantee_id, status, version_id | 按接收者及版本查统计权限 |
| surveys | questions.version_id | 按版本定位问卷及使用情况 |
| surveys | questions.series_id | 按系列定位问卷 |

数据库结构校验区分各集合 schema_version。users 和 responses 保持原校验；surveys 同时接受版本 1 和 2，其中版本 2 的题目必须有合法类型的 series_id 和 version_id。新增集合检查必填、类型、状态枚举和数组大小；版本来源、所有权、跨集合引用、快照相等和题内规则仍由后端检查。

不能直接把旧 `common.schema_version` 的 enum 从 [1] 改为 [2]，否则会破坏 users 和 responses；也不能仅给题目对象加字段，因为当前 `configure_questions` 对题目字段执行严格集合相等检查。

### 10. 跨问卷统计的查询口径

1. 接收具体 version_id，或接收 series_id 后按版本分别查询。拥有系列使用权者可读取该题的版本信息；仅有统计授权者只能读取已授权对应版本的必要快照。
2. 从自己的问卷引用以及当前有效 statistic_grants 得到允许查询的 `(survey_id, question_id, version_id)`，去重后校验问卷实际引用版本匹配。
3. 按允许的 survey_id 范围筛选 responses，展开 answers，并按精确的 survey_id 与 question_id 成对匹配，不能将两个独立 ID 列表当成笛卡尔组合。
4. 按原题型生成回答份数、选项计数、数字统计或内容。自己的问卷和共享授权同时覆盖同一题时只统计一次，过滤条件不重复展开同一答案。
5. 内容列表单独使用自己问卷加 allow_contents 授权的范围，不能复用更宽的基础统计范围。响应同时显示基础统计范围和内容可见范围，避免将内容条目数误认为全部回答数。
6. 按需求梳理中的边界约定生成数字分布，空数据、全部相同、数值 0 和自定义边界均有对应测试。现有整卷统计接口保留第一阶段返回语义。

对仅获得统计权限的用户，查询结果没有填写者身份、答卷 ID、逐条时间或 submission_key。授权可变，后续请求重新检查权限，不缓存跨用户权限结果；撤销不追溯删除用户已查看的结果。

同系列多个版本在同一问卷中出现时，每个版本独立计数。跨用户派生属于新系列，不自动合并来源数据。旧题未迁移或没有可确认的版本映射时不纳入新增统计。

### 11. 旧数据迁移和回退

#### 11.1 隔离与基线

第一阶段默认数据库名为 questionnaire，默认 MongoDB 端口为 27018。第二阶段配置独立数据库名 questionnaire_stage2；两阶段同时运行时另用应用端口，例如 8001。复制本地数据目录不等于已实现数据库隔离，不能直接启动第二阶段后就对默认数据库做迁移。

迁移前确认当前 URI、数据库名称和目标副本，完整备份后将旧业务数据复制到独立目标数据库；数据迁移期间停止目标服务写入。保留原 `_id`，以维持账号、问卷和答卷关系，且不修改第一阶段数据库。

记录迁移前用户数、问卷数、答卷数、各问卷的题目原字段和答卷摘要，以及原统计结果。备份和副本验证通过后才实施迁移；本文未执行这些数据库操作。

#### 11.2 可重复执行的步骤

1. 先扩展第二阶段校验器，使旧结构和新结构可同时读取；创建新增集合及索引。
2. 遍历旧问卷，每题按 `原问卷ID:原题ID` 生成 legacy_key，查找或创建对应系列，不按题干合并。
3. 查找或创建该系列 v1，规范化 content 但确认其业务含义与原题一致。迁移请求键从迁移键稳定生成，保证中途失败后重跑不重复建版本。
4. 将版本与系列引用补充到问卷题目，保留所有原字段和数组顺序；一份问卷的引用齐全后，通过原结构和更新时间条件作一次文档更新，并设置 schema_version 为 2。
5. 仅补充来源的迁移不更改问卷业务 updated_at，以保留历史元数据；后续真正的用户编辑才更新该值。迁移中发现原文档变化则记录冲突并停止处理该问卷，不能覆盖。
6. 不重写 responses，不改变答案值和其 question_id。旧问卷含空草稿时直接转换空 questions，不产生题目版本。
7. 校验版本映射完整、原字段一致、答卷数量和内容一致、原统计一致，再完成本次迁移。重复执行只补齐未完成部分。

迁移过程允许新增版本先于问卷绑定成功；未绑定的迁移产物有 legacy_key 可定位，重跑继续关联。只有问卷成功切为版本 2 后才进入新增的跨问卷统计，防止半迁移数据被误计。

#### 11.3 回退与失败处理

回退通过保留的迁移前目标数据库备份恢复至另一个独立数据库，并切换第二阶段配置验证，不删除或覆盖第一阶段数据。不在已接收第二阶段新增写入后直接执行破坏性降级；如发生此情况，先保存增量并制定数据保留方案。

迁移日志记录每份问卷的成功、跳过和错误，输出核对摘要，不记录密码哈希、密钥或完整答卷。迁移尚未完成时，原功能按旧结构兼容读取，新题库功能提示先完成迁移。

### 12. 程序调整范围

| 位置 | 计划改动 |
| --- | --- |
| app/database.py | 按集合维护版本校验、新增集合和索引，兼容旧文档 |
| app/models.py | 增加题目、版本、共享、题库和统计授权的严格输入模型 |
| app/domain.py | 分离原七字段题目投影与新增引用元数据，复用原校验和跳转处理器 |
| app/services.py | 保留 SurveyService 与 ResponseService，扩展快照绑定和权限；新增独立题目、题库与授权服务模块 |
| app/api.py 及新增路由 | 保留原接口，新模块增加版本、共享、题库、使用情况和跨问卷统计接口 |
| frontend | 在原问卷编辑页保留直接编题，增加保存题目、选题及版本替换入口，补充管理页面 |
| scripts | 增加独立目标数据库迁移及校验脚本，支持预览和重跑 |
| 配置与测试 | 第二阶段独立数据库和端口配置；回归原测试并增加版本、权限、迁移、统计用例 |

不能直接把含 ObjectId 引用的题目交给原配置函数，因为原函数拒绝未知字段。先拆分并验证引用，再将原七字段投影交给规则引擎；快照与版本比对使用规范化后的五项 content。所有入口使用同一个处理流程，避免预览、发布和提交行为不同。

旧接口传入原七字段题目时，依据原问卷内部 id 判断保留、编辑或新增，后端建立版本；不能因客户端省略引用字段就将已有题偷偷转为无来源题。旧结构读取兼容不等于允许已发布问卷重写结构。

多集合操作不假定本机 MongoDB 已配置副本集事务，优先使用不可变插入、单文档原子更新、唯一索引和可重试流程。业务文档保存前检查授权及引用，撤销按操作检查时生效；不承诺撤销能够追溯阻止已经通过检查的并发操作。实现阶段需验证故障中断及重试行为。

### 13. 开发前的验证清单

- 版本请求重试不重复写入；并发版本号唯一；恢复和分支来源清楚。
- 共享取消及归档后原引用仍可用，新引用和派生受限制。
- 题目版本内容不可被客户端篡改；草稿换版本不破坏跳转，发布后结构不能变更。
- 跨问卷统计不串题、不重复计数、不混合版本、不扩大授权。
- 旧数据迁移重跑不会重复生成题目；迁移失败后可继续，原统计不变。
- 运行时数据库和应用端口与第一阶段隔离，原自动测试和新验收场景均通过。

上述核心验证场景已纳入当前回归，完整结果见[第二阶段实现与验证](../测试/测试用例.md#第二阶段实现与验证)。迁移脚本输出汇总及原数据核对结果；原七字段题目投影位于 app/questions.py，未改写原规则处理器。本文涉及回退备份演练等操作约定，不代表本次额外执行过破坏性恢复演练。
